# Rules for every card

You are given one task card. Do what it says, and nothing else. You work in the repository
yourself: you open files, change them and run commands.

## The work

1. Follow the card's **Steps** in order. Where a step gives code, names or wording, use them
   exactly.
2. A file from `docs/plan/patterns/` is a recipe: it shows how work of this kind is done. Where it
   and the card differ, follow the card.
3. Write the tests the card names under **Tests**, with the names it gives.
4. Do not add a feature, an option, a field, a comment about your work, or a dependency that the
   card does not ask for.
5. Patient data in code and tests is made up: invented names, descriptions that start with
   "Demo:". Never a real-looking phone number, address or ID number.
6. Text a user reads is copied from the card exactly, with its curly apostrophes.

## In the repository

7. Change only the files listed under **Files**. Create no other file.
8. Read only what is listed under **Read first**, and only the lines it names. Do not explore the
   repository.
9. Do not edit a test you were given. Do not edit a generated file. Do not edit a migration that
   already exists.
10. Ignore the **Audit** section. It is for the person who checks your work.
11. Do not commit, push or switch branches. Leave your changes in the working tree.
12. When you are done, reply with: the files you changed, and the last line each command under
    **Run** printed.
13. Stop and say what happened, without guessing, if: a step is unclear; the code is not as the
    card describes it; a command fails twice with the same message.
